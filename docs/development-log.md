# 보험 나침반 개발·검증 기록

기록일: 2026-10-20 (Asia/Seoul). 대화에서 실제 수행한 작업과 도구 실행 결과만 기록합니다. 아래의 모의 응답 검사는 실제 OpenAI 호출과 구분합니다.

## 1. 최초 요구사항

대학원 「생성형 AI와 바이브 코딩」 과제 2를 위해 현재 `insurance-compass` 폴더에 동작하는 웹앱 구현을 요청받았습니다.

- HTML/CSS/Vanilla JavaScript, Vercel 정적 호스팅과 Node.js Serverless Function 사용
- 최상위 `index.html`, `style.css`, `app.js`, 시연 JSON, `api/explain.js` 분리
- 가상 계약 3~4건, 6가지 보장 유형 필터, 보험별/보장별 보기, 기본 쉬운 설명, 큰 글씨와 모바일 지원
- 누락 정보는 확인 필요로 표시하고 유사한 보장 이름을 혼동하거나 지급액을 확정하지 않기
- 공식 OpenAI SDK와 Responses API, 기본 `gpt-5-mini`, 서버 전용 환경변수, 허용 데이터 검사 및 비용 제한
- README, `.gitignore`, 실제 개발·오류·테스트 기록 작성
- GitHub push와 Vercel 배포는 수행하지 않기

## 2. 실제 구현 과정

1. 폴더가 비어 있음을 확인했고 Node.js 24.13.0, npm 11.6.2를 확인했습니다.
2. OpenAI 공식 문서의 Responses API·Structured Outputs·GPT-5 mini와 Vercel의 Function·파일 포함 설정을 확인했습니다.
3. HTML/CSS 화면, 가상 계약 4건과 보장 10개를 만들었습니다. 조회·검증·표시 형식을 `services/insurance-service.js`로 분리했습니다.
4. 계약 조회, 6개 필터, 보기 전환, 요약표, 기본 설명·주의사항, 글씨 크기 4단계와 저장을 구현했습니다.
5. 서버는 클라이언트의 허용 ID를 검증한 뒤 시연 JSON에서 필요한 정보만 읽도록 했습니다. API 입력 길이 제한, 요청 제한, 캐시, 동시 중복 생성 방지, 오류 응답을 구현했습니다.
6. 빌드는 공개 파일만 `dist/`에 복사하고, API는 프로젝트 최상위 `api/`에 유지하도록 구성했습니다.
7. Node 테스트 15개와 Playwright 테스트 7개를 작성하고 최초 실행에서 모두 통과했습니다.
8. 문서 작성 전에 작업 턴이 중단되었습니다. 후속 검증 시작 시 README와 이 개발 기록이 아직 없다는 사실을 확인했습니다.

## 3. 실제 발생한 환경 문제

| 상황 | 원인·증거 | 조치와 결과 |
| --- | --- | --- |
| 최초 `npm install` 실패 | 제한된 실행 환경에서 npm 레지스트리 DNS `ENOTFOUND` | 대기 중 명령을 중단하고 네트워크 권한을 사용해 재실행. 6개 패키지 설치, 당시 audit 취약점 0건 |
| 최초 Playwright 서버 실행 실패 | `listen EPERM 127.0.0.1:4173` | 로컬 서버·Chrome 실행 권한으로 재실행. 최초 7개 테스트 통과 |
| 후속 검증 로그의 색상 경고 | `NO_COLOR`와 `FORCE_COLOR`가 함께 설정됨 | 실행 환경 경고이며 테스트 실패가 아니므로 앱 코드를 변경하지 않음 |

자동 승인 거절은 발생하지 않았습니다. 실제 OpenAI 오류를 경험한 것처럼 기록하지 않았습니다.

사용자는 생성 파일·실제 기능 확인, 기존 테스트 재실행, 언어 점검, Vercel 경로 점검, 결과 기록을 요청했습니다.

- `npm run check`: 통과. JS 11개 문법, JSON, 시연 데이터 계약, 공개 코드의 키 참조 검사

수정하기 전에 사용자에게 원인과 조치 방향을 설명했습니다.

| 발견 사항 | 조치 |

## 7. Vercel 경로 점검

- `api/explain.js`는 서버 진입점으로 존재하고 ESM import 및 공식 SDK import가 로컬 Node.js에서 성공했습니다.
- 해당 실제 진입점을 함수로 호출해 GET=405, 키 미설정 POST=503을 확인했습니다. HTTP 플랫폼 라우팅을 실행한 검사는 아닙니다.
- 빌드된 HTML·JS가 참조하는 CSS, JS, 아이콘, 시연 JSON, 조회 어댑터가 `dist/`에 존재합니다.
- `dist/`에 `api/`, `server/`, `node_modules/`, 환경변수 파일을 포함하지 않습니다.
- `vercel.json`에 API를 덮어쓰는 rewrite/routes 설정이 없습니다.
- `includeFiles` 대상의 시연 JSON이 실제로 존재합니다.
- `package.json`은 ESM, 운영 OpenAI 의존성, Node.js 24.x를 지정합니다. [Vercel 지원 버전 공식 문서](https://vercel.com/docs/functions/runtimes/node-js/node-js-versions)에서 24.x 지원을 확인했습니다.
- Root Directory를 `dist`로 설정하거나 정적 산출물만 업로드하면 API가 누락될 수 있으므로 README에 올바른 프로젝트 최상위 경로를 명시했습니다.

## 8. 확인하지 않은 범위와 남은 한계

- 실제 OpenAI API 요청, 계정의 `gpt-5-mini` 접근 권한, 결제/한도, 생성 설명의 품질은 검증하지 않았습니다. 실제 키를 출력하거나 코드에 추가하지 않았습니다.
- 실제 Vercel 배포·클라우드 Function 번들링·라우팅·환경변수·도메인·배포 보호는 검증하지 않았습니다. `vercel build`, `vercel dev`, push, 배포를 실행하지 않았습니다.
- Playwright는 데스크톱 Chrome과 모바일 크기 에뮬레이션입니다. 실제 스마트폰·Safari·Firefox·스크린리더·고령층 사용성 검사는 수행하지 않았습니다.
- 접근성 자동 검사 결과는 전체 접근성 준수를 보장하지 않습니다.
- 인메모리 호출 제한은 여러 Function 인스턴스에 걸친 강제 비용 상한이 아닙니다. 인증과 공유 제한은 이번 버전에 없습니다.
- 기본 설명은 시연 원칙에 대한 구현 단계의 문구 검토이며 보험 전문가의 감수를 받지 않았습니다.
- 향후 기능 목록은 README에만 기록했으며 구현하지 않았습니다.
